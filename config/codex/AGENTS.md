# 개념 설명시에

- 핵심 영문 용어의 원문과 한국어 의미를 함께 설명한다.
- 약어는 최초 사용 시 전체 영문 명칭을 밝힌다.
- 약어를 구성하는 각 단어의 뜻과 문맥상 의미를 설명한다.
- 직역과 실제 기술적 의미가 다르면 구분해서 설명한다.
- 명칭이 붙은 이유가 개념과 관련 있다면 함께 설명한다.

# 작업 시작 규칙

- `?`가 포함된 질문은 작업 요청으로 해석하지 않는다. 질문에 답하거나 계획만 제시한다.
- `고쳐줘`, `해줘`, `시작해` 등의 명령형 표현이 있으면 작업을 시작한다.
- 작업 시작 시 실제 사용할 스킬 이름과 목적을 짧게 안내하고, 도중에 추가되는 스킬도 최초 사용 시 안내한다.

# 유니티 작업시 규칙
- Unity 에디터 조회·조작 또는 Unity CLI 실행이 필요한 작업은 [unity-cli](skills/unity-cli/SKILL.md) 스킬을 반드시 읽고 따른다.
- Unity CLI 실행에는 `C:\Users\tkdal\AppData\Local\Unity\bin\unity.exe` 절대 경로를 사용한다.
- 실행이 필요한 작업에서는 먼저 Unity CLI 사용 가능 여부를 확인하고, 사용할 수 없으면 해당 작업을 중단하고 연결 안내를 제공한다.
- 설명이나 계획만 요청한 경우에는 Unity CLI를 실행하지 않는다.

# 테스트 산출물 저장 위치

- 테스트용 임시 파일, 결과표, 로그, 스크린샷, 덤프 등 로컬 산출물은 실제 작업 대상 프로젝트를 기준으로 저장한다. 사용자가 저장 경로를 지정하면 그 경로를 따른다.
- Unity 프로젝트는 저장소 유무와 관계없이 해당 Unity 프로젝트의 `Assets/Ignore/<작업명>/`를 우선 사용한다.
- 일반 프로젝트에 로컬 저장소가 있으면 해당 저장소 루트의 `Ignore/<작업명>/`에 저장한다.
- 일반 프로젝트에 로컬 저장소가 없으면 해당 프로젝트 루트의 `Ignore/<작업명>/`에 저장한다.
- 저장소가 있는 경우 해당 경로가 버전 관리 추적 제외 설정에 포함되는지 확인한다.

# 공통 작업 검증
- 별도의 지시가 없다면 변경 범위에 적절한 검증을 수행하지 않는다.
- 기본적으로 검증없이 작업을 하도록하고 사용자가 `검증 포함 작업해줘`라고 요청하면 검증을 하도록한다.
- 사용자가 `검증 포함 작업해줘`라고 명시하면 컴파일, 오류 조회, 오류 수정을 한다.
- 검증을 생략하더라도 대상 확인, 변경 적용 여부 확인, 변경 파일 확인은 수행한다.
- 검증을 하던 말던 최종 응답에 이를 명시한다.
- 파일 삭제나 권한 변경 등 안전 관련 확인은 검증 생략 요청과 관계없이 수행한다.

# Unity 작업 검증
- 별도의 명령이 없다면 Unity Play Mode 검증은 수행하지 않는다.
- 코드 변경 후 Unity CLI를 통해 컴파일 오류와 예외만 확인한다.
- 검증을 하든 하지 않든 유니티를 포그라운드로 만들었을떄 이미 컴파일이 되어 있도록 마지막에는 유니티 컴파일 명령을 내리도록 하고 컴파일 종료를 기다리지말고 완료보고를 하도록 한다.
