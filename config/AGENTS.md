# 공통

## 응답 언어
- 항상 한국어로 답한다.
- 선택지도 한국어로 보여준다.

## 작업 진행
- `?`가 포함된 질문은 작업 요청으로 해석하지 않는다. 질문에 답하거나 계획만 제시한다.
- `고쳐줘`, `해줘`, `시작해` 등의 명령형 표현이 있으면 작업을 시작한다.
- 모든 응답의 첫 줄에 이번 응답에서 쓰는 스킬 이름과 목적을 "사용 스킬: `이름` — 목적"으로 안내한다. 쓰는 스킬이 없으면 "사용 스킬: 없음"으로 쓴다. 도중에 스킬이 추가되면 처음 쓸 때 다시 안내한다.
- 검증은 사용자가 지시하거나 검증 계획에 동의한 경우에 수행한다.
- 적용한 스킬이 시각 검증을 기본으로 정하면 별도 요청 없이 해당 시각 검증을 수행한다. 사용자가 검증이나 시각 확인을 생략하라고 요청하면 그 요청을 우선한다.
- 검증 수행 여부를 응답의 끝에 짧고 간략하게 표시한다.

## 상황별 필수 스킬
- 아래 상황에 해당하는지 작업 전에 확인하고, 해당하면 사용자에게 묻지 않고 해당 스킬을 사용한다.
- C# 코드를 작성·수정할 때: `csharp-project-style`
- PackageDev와 자체 패키지 서브모듈을 커밋·푸시·배포할 때: `workflow-package-dev-push`
- 기능 구현 전에 계획을 보여 줄 때: 결과물은 `show-result`로 먼저 보여 주고, 그 아래에 계획을 설명한다. 결정할 것은 제안과 함께, 확인받을 것은 번호 목록으로 묻는다.

## 자료 찾기·저장
- 프로젝트 밖의 자료를 찾거나 저장할 때는 먼저 `~/.agents/폴더 안내.md`를 읽고 판단한다. 파일이 없으면 이 규칙은 건너뛴다.

# 프로젝트 작업

## 임시 산출물 저장 위치
- 저장소는 git, Plastic SCM, Perforce 등 버전 관리 저장소를 모두 포함한다(`.git`, `.plastic`, `.p4config` 등으로 확인하고, Perforce는 필요하면 `p4` 명령으로 확인).
- 임시 산출물(임시 파일, 임시 테스트 코드·테스트 프로젝트, 결과표, 로그, 스크린샷, 덤프)은 사용자가 지정한 경로에 저장한다. 지정이 없으면 아래를 위에서부터 확인해 처음 맞는 것을 따른다.
  - 작업 대상이 저장소이고 Unity 프로젝트면: `Assets/Ignore/<작업명>/`
  - 작업 대상이 저장소이면: 저장소 루트의 `Ignore/<작업명>/`
  - 작업 대상이 저장소가 아니면(Unity 프로젝트 포함): `D:\WorkSpace\Scratch\<작업명>/`
- 저장소에 저장할 때는 그 경로가 해당 저장소의 제외 목록(`.gitignore`, `ignore.conf`, `.p4ignore` 등)에 들어 있는지 확인하고, 없으면 제외 규칙을 추가한다.

## 개발 문서 보관소
- 프로젝트의 기획·설계·작업 계획·순서도 등 개발 문서는 프로젝트 루트의 `<프로젝트명>.DevDocs/` 폴더에 둔다. 이 폴더는 Obsidian 보관소다.
- 위치는 프로젝트 루트에서 이름이 `.DevDocs`로 끝나는 폴더를 찾아 정한다. 없으면 `<프로젝트명>.DevDocs/`를 만들고, `<프로젝트명>`은 프로젝트 루트 폴더 이름을 쓴다.
- Obsidian 링크와 임베드 경로는 이 보관소 루트를 기준으로 쓴다.

## 코드 탐색
- 심볼과 호출 관계는 codebase-memory-mcp로 먼저 찾는다. 범위를 좁혀 `limit` 3~5, `depth` 1부터 시작한다.
- 문자열·리터럴 검색, 결과가 없거나 인덱스에 빠진 경로, Unity 직렬화·리플렉션·`#if` 분기가 얽힌 경우는 rg로 찾고 필요한 범위만 읽는다.
- 수정 전에는 선언·구현·호출부를 실제 파일에서 확인한다. 인덱스 결과만으로 판단하지 않는다.

## Unity 프로젝트
- Unity프로젝트 관련 작업시에 Unity CLI 스킬을 사용한다.
- Unity프로젝트 내의 코드를 수정한 경우 작업이 완료된 뒤에 내가 한참있다가 유니티를 포그라운드로 만들었을때 그때 컴파일 되는 화면을 기다리지 않도록 백그라운드 상태의 유니티에게 UnityCLI를 통해 컴파일 시도를 명령한다.
