# 공통 규칙
- 항상 한국어로 답한다.
- 선택지도 한국어로 보여준다.

# 작업 관련 규칙
- `?`가 포함된 질문은 작업 요청으로 해석하지 않는다. 질문에 답하거나 계획만 제시한다.
- `고쳐줘`, `해줘`, `시작해` 등의 명령형 표현이 있으면 작업을 시작한다.
- 작업 시 실제 사용할 스킬 이름과 목적을 짧게 안내하고, 도중에 추가되는 스킬도 최초 사용 시 안내한다.
- 별도의 검증해줘 등의 검증 지시나 검증 계획에 대한 동의 등 검증에 대한 의사표현이 없어 보이면 변경 범위에 대한 적절한 검증을 수행하지 않는다
- 검증 수행 여부를 응답의 끝에 짧고 간략하게 표시한다.

# 상황별 필수 확인 스킬
- 아래 상황에 해당하는지 작업 전에 확인하고, 해당하면 사용자에게 묻지 않고 해당 스킬을 사용한다.
- C# 코드를 작성·수정할 때: `csharp-project-style`
- PackageDev와 자체 패키지 서브모듈을 커밋·푸시·배포할 때: `package-dev-release`

# Unity 프로젝트 관련 작업 규칙
- Unity프로젝트 관련 작업시에 Unity CLI 스킬을 사용한다.
- Unity프로젝트 내의 코드를 수정한 경우 작업이 완료된 뒤에 내가 한참있다가 유니티를 포그라운드로 만들었을때 그때 컴파일 되는 화면을 기다리지 않도록 백그라운드 상태의 유니티에게 UnityCLI를 통해 컴파일 시도를 명령한다.

# 프로젝트 작업 시 임시 산출물 저장 위치
- 임시 산출물(임시 파일, 임시 테스트 코드·테스트 프로젝트, 결과표, 로그, 스크린샷, 덤프)은 사용자가 지정한 경로에 저장한다. 지정이 없으면 프로젝트 루트(저장소가 있으면 저장소 루트)의 `Ignore/<작업명>/`에 저장한다.
- 단, Unity 프로젝트는 `Assets/Ignore/<작업명>/`에 저장한다.
- 저장소가 있으면 그 경로가 `.gitignore` 등 버전 관리 제외 목록에 들어 있는지 확인하고, 없으면 제외 규칙을 추가한다.

# 프로젝트 코드 탐색
- 심볼과 호출 관계는 codebase-memory-mcp로 먼저 찾는다. 범위를 좁혀 `limit` 3~5, `depth` 1부터 시작한다.
- 문자열·리터럴 검색, 결과가 없거나 인덱스에 빠진 경로, Unity 직렬화·리플렉션·`#if` 분기가 얽힌 경우는 rg로 찾고 필요한 범위만 읽는다.
- 수정 전에는 선언·구현·호출부를 실제 파일에서 확인한다. 인덱스 결과만으로 판단하지 않는다.
