# 게임 기획서 작성과 갱신

작업 전에 [예시 캔버스](assets/카페%20기획서.canvas)를 읽는다. 예시는 게임 개요 및 레시피 표와 주문·제작·서빙·설정 흐름을 함께 보여 준다. 예시 자체를 열 때는 `assets/`를 보관소 루트로 사용한다.

## 게임당 대표 기획서 하나

대상 게임의 개발 문서 보관소에서 기존 대표 기획서를 먼저 찾는다. 이름이나 위치가 달라도 해당 게임의 기획서가 있으면 그 파일을 갱신한다. 처음 만드는 경우에는 사용자가 지정한 위치를 우선하고 기본은 `<프로젝트명>.DevDocs/기획/<게임명> 기획서.canvas`로 한다.

수치를 바꾸면 표를 갱신하고, 판정 방식이 바뀌면 관련 문서와 플레이 흐름을 함께 갱신한다.

전용 시안과 표는 캔버스 옆의 `<게임명> 기획서.Data/`에 둔다. 하위 표에 딸린 자료는 [Obsidian 자료 정리](../organize-obsidian-assets/SKILL.md) 규칙을 따른다. 예시를 다른 위치에 복사할 때는 캔버스의 파일 경로와 Base의 폴더 필터를 대상 보관소 루트 기준으로 갱신한다.

## 표기 규칙

기존 파일에 범례가 빠져 있으면 추가한다. 표기를 바꾸면 범례와 본문에 함께 반영한다.

- 노드 정의는 본문과 동일한 도형 안에 이름과 뜻을 넣는다. 시작·종료는 보라색 캡슐, 장면·행동·상태는 직사각형, 조건 판단은 중앙에 짧은 질문을 넣은 마름모다. 캡슐과 마름모는 Advanced Canvas의 shape와 textAlign 속성을 사용한다.
- 범례에 문서 노드와 데이터 표의 용도도 적는다.
- 색의 뜻을 따로 정의한다. 초록은 정상 진행과 플레이어의 선택, 주황은 실패나 예외 대응이다. 설정에서 플레이어가 선택한 앱 종료도 정상 진행이다.
- 라벤더색(#B3A1C9) 흐름 그룹은 시작점부터 이어지는 하나의 흐름을 감싼다. 연청회색(#9DBBCB) 기능 그룹은 관련 장면이나 행동을 그 안에 묶는다.
- 연결선 정의는 짧은 노드 두 개와 **실제 화살표**로 그린다. 초록 단방향은 다음 단계, 초록 양방향은 열기·복귀, 주황 단방향은 예외 대응이다. 조건이나 조작을 선에 적는다. 반복은 원래 노드로 직접 돌아가는 일반 단방향 선으로 표현한다.

## 캔버스 배치

- **상단**에 노드·그룹·연결선 정의를 둔다. 아래에는 문서 영역과 흐름 영역의 윗선을 맞추고 중립색 제목과 여백으로 구분한다.
- **왼쪽 문서 영역**에는 개요·조작·판정·보상을 Markdown 노드로 작성하고, 레시피·가격 등은 원본 표를 파일 노드로 배치한다.
- **오른쪽 흐름 영역**에서는 메인 흐름을 위에서 아래로 잇고 독립 흐름은 옆에 둔다. 각 흐름의 첫 장면에 시작 표기를 쓰고, 종료와 복귀를 구별한다. 왕복 기능은 한편에 모은다.
- **장면 카드**는 제목·핵심 정보·설명 순으로 쓰고, 시안은 설명 아래에 원본 비율로 크게 둔다. 현재 구현 화면에는 그 사실을 표시한다. 카드 크기와 간격은 내용과 화살표 문구에 맞추고, 이동할 때는 설명·이미지·연결선을 함께 유지한다.

## 시각 확인

사용자가 시각 확인을 요청한 경우에만 전체 배치와 변경 구간의 확대 화면을 살펴보고, 겹침이나 잘림을 조정한다.
