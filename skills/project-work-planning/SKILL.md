# 프로젝트 작업 계획 관리

## 두 문서의 역할

- **전체 계획.md**: 프로그램 완성까지 필요한 큰 기능의 체크리스트와 후속 작업의 확정 사항. 큰 기능 전체가 구현됐을 때 완료 표시하고 항목을 유지한다. 일부 기반 코드만 완성됐다고 큰 항목을 완료 처리하지 않는다.
- **작업 계획.md**: 지우지 않는 **고정 방침**과 이번 한 건의 **현재 작업** 영역. 현재 작업에만 구체적인 변경 대상·범위·순서·완료 조건을 적는다. 작업이 끝나면 현재 작업 영역을 비우고 다음 작업을 미리 채워 넣지 않는다.
- 앞으로 필요한 합의를 잃지 않도록 후속 사항을 전체 계획에 먼저 옮긴 뒤 현재 작업에서 제거한다. 완료된 설계의 상세 설명은 코드·프로젝트 문서에 남기며 계획서를 완료 이력으로 채우지 않는다.

## 적용 범위와 위치

1. 현재 대상 프로젝트와 적용되는 사용자·저장소 지침을 확인한다. 다른 프로젝트의 계획과 섞지 않는다.
2. 사용자가 지정한 두 파일 또는 기존 동등한 계획 문서를 먼저 찾는다. 이미 있으면 이름·위치를 유지하며 중복 문서를 만들지 않는다.
3. 파일이 없고 문서 관리가 필요한 작업이면 프로젝트의 로컬 산출물 위치 규칙을 따른다. 일반적인 후보는 프로젝트의 Ignore/이며, Unity 등 별도 규칙이 있으면 그 규칙을 우선한다. 기존 위치·권한으로 결정할 수 없을 때만 확인한다.
4. 새로 생성할 때 전체 계획과 작업 계획 두 파일만 준비한다. 로컬 제외 여부를 확인하고, 추적 정책 변경은 사용자·저장소 지침에 맞춘다. 개인 절대경로나 특정 프로젝트 정책을 스킬의 공통 기본값으로 복제하지 않는다.

## 계획 수립·변경

- 먼저 전체 계획의 관련 항목과 작업 계획의 고정 방침·현재 작업을 읽는다.
- 이번 요청 범위를 현재 작업에 적는다. 작업 대상 파일·클래스·함수, 구현할 동작, 제외 범위, 완료 조건을 구분한다. 필요할 때만 세부 순서를 추가한다.
- 확정한 사항과 제안을 구분한다. 대화에서 승인되지 않은 제안을 고정 방침으로 만들지 않는다.
- 범위가 변경되면 이전 계획에 단순히 덧붙여 모순을 남기지 않는다. 취소된 항목은 제거하고, 미뤄진 항목과 관련 합의는 전체 계획으로 옮긴다.
- 이미 다른 작업이 진행 중이면 그 현재 작업을 통째로 덮어쓰지 않는다. 요청이 보충·교체·별도 작업 중 무엇인지 구분하고 필요한 경우에만 확인한다.
- 고정 방침에는 해당 프로젝트에서 명시적으로 합의한 지속 규칙만 적는다. 예를 들어 마이그레이션 금지는 사용자가 정했을 때만 기록한다. 방침 변경 지시가 없으면 그대로 유지한다.

## 구현 중

- 현재 작업을 기준으로 구현하고 완료 조건에서 빠진 항목이 없는지 확인한다.
- 새로 발견한 별도 개선 사항은 전체 계획에 제안 또는 미확정으로 남길 수 있지만, 요청 범위에 자동으로 포함하지 않는다.
- 스킬이나 계획 문서에 항목이 있다는 사실은 실행·삭제·커밋·푸시·배포 승인이 아니다. 사용자 요청과 현재 권한 범위를 따른다.
- 설명만 요청했거나 파일을 수정하지 말라고 했다면 그 제약을 우선한다. 계획 문서 기록과 실제 코드 구현도 별개다.

## 부분 완료·완료

- **부분 완료**: 완료한 세부 항목은 현재 작업에서 제거하되 아직 필요한 의존 정보·제약은 유지한다. 미완료 항목과 막힌 이유를 남긴다. 임의로 전체 완료 처리하지 않는다.
- **이번 작업 완료, 큰 기능 미완료**: 후속 작업과 필요한 합의를 전체 계획에 보관하고 현재 작업은 비운다. 전체 계획의 큰 기능 체크는 미완료로 유지한다.
- **큰 기능까지 완료**: 전체 계획의 해당 항목을 완료 표시한다. 현재 작업은 비우고 고정 방침은 그대로 둔다.
- 구현 완료와 검증 완료를 구분한다. 검증 수행 여부는 사용자·프로젝트 지침을 따르며, 실행하지 않은 검증을 통과했다고 적지 않는다. 남은 검증은 전체 계획의 상태 메모에 명시한다.
- 완료 직전 두 문서를 다시 읽어 후속 합의 누락, 잘못된 완료 표시, 현재 작업에 남은 다음 작업, 고정 방침 손실을 확인한다.
- 보고에는 변경한 계획 파일과 실제 검증 여부를 짧게 알린다. 문서 정리만 요청받았다면 코드 작업을 시작하지 않는다.

## 다음 작업 조회

전체 계획의 미완료 기능과 상태를 근거로 다음 작업을 제안한다. 사용자가 아직 시작하지 않은 다음 작업을 현재 작업 영역에 자동으로 채우지 않는다. 구체적인 계획 수립을 요청하면 그때 현재 작업에 범위를 기록한다.

## 예시

새 문서의 형태나 계획 변경·부분 완료·최종 완료 판단이 필요하면 [references/examples.md](references/examples.md)를 읽는다. 예시의 기능명과 고정 방침은 설명용이며 다른 프로젝트에 그대로 강제하지 않는다.
