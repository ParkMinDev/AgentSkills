# PackageDev Release

## 범위와 근거
- 사용자가 지정한 저장소·패키지·대상 프로젝트를 확인하고 현재 Git 상태와 적용되는 프로젝트 지침을 읽는다. 특정 패키지만 요청하면 관련 없는 변경을 스테이징하거나 배포하지 않는다.
- 아래 의존성 파일 이름은 기존 프로젝트 규약이다. 실제 저장소에서 `parkmin-upm.json` 등으로 이전했다면 PackageManager가 읽는 파일과 버전 비교 방식을 확인해 같은 의존성 일치 원칙을 적용한다. 없는 파일을 임의로 새로 만들지 않는다.
- 배포할 버전과 범위를 먼저 결정한다. 연쇄 갱신이 명시적으로 제한된 작업 범위와 충돌하면 영향 관계와 선택지를 설명하고 범위 결정을 받는다. 충돌을 피하려고 배포 버전을 임의로 재사용하지 않는다.
- Git 작업은 터미널에서 수행한다. 기존 사용자 변경을 보존하며 푸시 실패 시 원인을 확인하고, 강제 푸시나 원격 이력 덮어쓰기로 우회하지 않는다.

## 배포 규칙
- 깃 푸시에는 Unity MCP를 사용하지 않는다.
- PackageDev와 그 아래 서브모듈들이 작업 범위이다.
- 작업 범위의 미스테이징 변경을 스테이징한 뒤, 스테이징된 차이를 기준으로 CHANGELOG와 커밋 메시지를 작성한다. 추가한 배포 메타데이터도 스테이징하고 최종 차이를 확인한 뒤 커밋·푸시한다.
- 특정 프로젝트에 적용해달라고 하는 경우에만 그 프로젝트의 매니페스트를 업데이트하고 특정 프로젝트를 언급하지 않는 경우에는 푸쉬까지만 수행한다.
- 특정 프로젝트에 적용할 때는 매니페스트만 업데이트하고 호환성 검사, 대상 프로젝트 오류 검출, 수정은 수행하지 않는다
- 패키지를 커밋·푸시할 때 `package.json`과 `parkmin-dependencies.json`의 의존성이 실제 사용하는 공개 API를 제공하는지 확인한다.
- 현재 PackageManager는 `parkmin-dependencies.json`의 선언 버전과 설치 버전을 정확히 비교한다. 자체 패키지 간 의존 버전은 최종 배포할 버전과 일치시킨다.
- 패키지 버전이 변경되면 공개 API 변경 여부와 관계없이 PackageDev의 모든 자체 패키지에서 해당 패키지를 참조하는 `parkmin-dependencies.json`을 찾는다.
- 영향을 받는 후속 패키지들의 의존 버전·패키지 버전·CHANGELOG를 함께 갱신한다. 후속 패키지의 버전 변경으로 영향을 받는 패키지까지 연쇄적으로 반영한다.
- 의존성 메타데이터만 변경된 후속 패키지는 패치 버전 증가를 기본으로 한다.
- 커밋 전에 전체 영향 범위와 최종 버전을 먼저 결정한다. 같은 배포 작업에서 하나의 패키지 버전을 중복 증가시키지 않는다.
- 선행 의존 패키지부터 후속 패키지 순서로 커밋·푸시하고, 마지막에 PackageDev의 서브모듈 참조를 갱신한다.
- 순환 의존성이 발견되면 버전을 반복 증가시키지 않고 관계를 보고하여 처리 방침을 정한다.
- 푸시 전 자체 패키지 간 최종 의존 버전의 일치 여부를 확인한다. 기존 불일치가 발견되면 이번 갱신 범위에 포함하고, 해결하지 못한 항목은 완료 보고에 명시한다.

## 완료 보고
- 커밋·푸시한 저장소, 커밋 식별자, 최종 버전과 대상 프로젝트의 매니페스트 반영 여부를 보고한다.
- 추가·수정·삭제한 파일을 표시하고, 50개 이상이면 50개까지 표시한 뒤 나머지 수를 밝힌다.
- 의존성 메타데이터 확인과 컴파일·실행 검증을 구분한다. 실제 수행한 확인, 생략한 검증, 미해결 의존성 불일치를 명시한다.
