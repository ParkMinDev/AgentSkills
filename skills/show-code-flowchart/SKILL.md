# 코드 순서도

작업 전에 [예시 순서도](assets/예시%20순서도.canvas)를 읽고 표기를 따른다. 아래는 예시만으로 알 수 없는 규칙이다.

## 근거
- 실제 함수와 호출부를 읽고, 노드를 실제 함수·분기·호출에 대응시킨다. 계획은 `[예정]`, 설명용은 `[가상 예시]`로 표시하고 없는 함수를 만들어 넣지 않는다.
- Canvas 작업만으로 빌드·실행·측정을 하지 않는다. 측정을 요청받으면 [측정 규칙](references/measurement.md)을 읽는다.

## 파일
- 위치는 AGENTS.md 개발 문서 보관소 규칙의 `<프로젝트명>.DevDocs/code-flowchart/`다. 링크는 보관소 루트 기준으로 쓴다(`![[code-flowchart/런처 순서도.canvas]]`).
- 이름은 `<클래스 경로>.<함수명> 순서도.canvas`다. 여러 진입점을 묶은 대표 그림은 기존 이름(예: `런처 순서도.canvas`)을 유지한다. 계획 단계 변형본은 원본을 복사해 `<원본 이름>.temp.canvas`로 만들고 머리말에 원본과 기준 설계를 적는다.
- 기존 Canvas는 노드·선 ID, 배치, 색, 플러그인 속성을 유지하고 바뀐 부분만 고친다. Obsidian에 열린 Canvas는 사용자가 편집하지 않을 때 쓴다.

## 그리기
- 맨 위에 **노드 설명 범례**를 둔다. 처음 보는 사람이 범례만 보고 그림을 읽을 수 있어야 한다. 측정 조건처럼 글로 설명할 내용은 범례 옆 카드에 둔다.
- 위에서 아래로 읽게 배치하고 분기선에 실제 조건을 쓴다.
- 함수를 펼칠 때는 함수 영역(그룹)으로 감싸고, 영역 제목에 `클래스.함수`, 영역 안 시작 카드에 실제 선언부를 쓴다. 펼치지 않는 함수는 하위 함수 호출 노드로 접는다. 같은 처리를 상위와 하위에 중복해 그리지 않는다.
- 병렬 실행은 바깥 영역 하나와 흐름별 내부 영역으로 그리고, 내부 영역 제목에 작업자 수를 쓴다. 실선은 실행 순서, 점선은 대기열·이벤트 전달이다. 큐가 잠깐 빈 것을 종료로 그리지 말고 모든 대상 완료와 작업자 합류를 그린다.
- 노드 색은 실제 비용으로 정한다. 입력·장치·네트워크에 따라 달라지면 카드에 적는다.

## 변경·삭제·측정 표시
- 이번 변경에서 추가·수정한 노드에만 `revisionEmphasis: current`(노드 색 광택)를 붙이고 이전 갱신의 표시는 지운다. 새 Canvas에는 붙이지 않는다.
- 없어지는 노드는 맨 아래 빨강 삭제 영역에 노드 하나씩 둔다. 계획 단계는 그룹 제목과 본문에 `삭제 예정`, 작업 후 갱신은 `삭제`로 쓴다. 본문에 원래 위치, 삭제 전 내용, 대체한 노드를 적고 흐름과 잇지 않는다. 다음 갱신에서 목록을 교체하거나 영역을 지운다.
- 메모리 피크는 `memoryPeak: observed`(모서리 배지)를 개별 노드에만 붙이고 그룹에는 수치만 쓴다. 변경 표시와는 별개다.

## 스타일
- 광택, 배지, 1.7배 글꼴은 [CSS](assets/canvas-node-emphasis.css)와 Advanced Canvas 확장이 있어야 보인다. 허용된 보관소의 `.obsidian/snippets/`에 복사해 활성화하고 다른 조각과 설정은 건드리지 않는다.
- 노드 크기는 내용에 맞게 잡고 글꼴 배율 때문에 일괄 확대하지 않는다. 글자가 잘리는 카드만 늘리고, 마름모는 중앙 폭이 좁으니 문장을 짧게 쓴다.
- 형식 근거: [JSON Canvas 규격](https://jsoncanvas.org/spec/1.0/), [Advanced Canvas 규격](https://github.com/Developer-Mike/obsidian-advanced-canvas/blob/main/assets/formats/advanced-json-canvas/spec/1.0-1.0.md)
