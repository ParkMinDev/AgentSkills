# Text Tree

## 근거와 범위
- 먼저 요청 대상, 루트, 표현할 부모·자식 관계를 판단한다. 특정 분야만 지원하는 것으로 제한하지 않는다.
- 실제 구조 설명이면 관련 소스·파일 목록·에디터 조회 결과 등에서 구조를 확인한다. 설계 제안, 사용자 제공 정보, 실제 조회 결과를 구분한다.
- 트리를 만들기 위해 존재하지 않는 계층을 추가하지 않는다. 설명 목적으로 재분류한 경우에는 설명용 분류라고 밝힌다.
- 관계나 범위가 불명확하면 문맥에서 결정한다. 선택에 따라 의미가 크게 달라지고 근거가 없을 때만 질문한다.
- 설명 요청만으로 파일·씬·프리팹을 수정하거나 빌드·재생하지 않는다. Unity 에디터 조회는 적용되는 Unity CLI 지침과 unity-cli 스킬을 따른다.

## 공통 표현
- 언어 식별자가 `text`인 코드 블록을 사용하고 `├─`, `└─`, `│`와 일정한 들여쓰기로 부모·자식 관계를 표시한다.
- 원래 이름과 관계를 유지한다. 실제 순서가 의미 있으면 보존하고, 정렬하거나 생략할 때는 의미를 바꾸지 않는다.
- 한 줄에는 한 항목을 표시한다. 필요하면 `— 짧은 역할 설명`을 덧붙이되 모든 항목에 자명한 설명을 반복하지 않는다.
- 관계의 기준은 필요할 때 트리 앞에 짧게 밝힌다. 조직·분류·작업·데이터 등 새로운 대상은 그 의미에 맞는 일관된 표기를 선택한다.
- 다중 부모·공유 항목·순환 참조는 정식 항목을 한 곳에 표시하고 나머지 위치에 `→ 경로 참조`로 나타낸다. 동일 항목을 무한히 펼치거나 참조를 실제 소유·하위 관계로 바꾸지 않는다.
- 동명이인은 전체 경로나 식별에 필요한 정보로 구분한다. 확인되지 않은 상태나 관계는 단정하지 않는다.
- 주요 항목만 표시했다면 생략 사실과 범위를 밝힌다. 전체를 요청하면 임의로 생략하지 않으며, 크면 루트별로 나누어 제시한다.
- 핵심 영문 용어는 한국어 의미와 함께 설명하고, 약어는 최초 사용 시 전체 명칭과 문맥상 의미를 밝힌다. 실제 이름과 코드 식별자는 보존한다.

## Unity GameObject와 Component
- 한 줄은 GameObject 하나이며 `오브젝트 이름 [컴포넌트 타입, 컴포넌트 타입]` 형식으로 표시한다.
- 가지선은 GameObject의 실제 부모·자식 관계만 나타낸다. 부착된 Component를 별도 자식 노드로 나열하지 않는다.
- 실제 확인한 컴포넌트 이름을 나열한다. Transform과 RectTransform을 혼동하지 않고, 동일 타입이 여러 개면 중복을 보존하거나 개수를 명시한다.
- 일부 컴포넌트만 표시할 때는 생략 사실을 밝힌다. 비활성 오브젝트·비활성 컴포넌트·누락 스크립트는 확인했고 설명에 필요할 때 구별해 표시한다.
- 다른 오브젝트를 참조하는 필드는 계층에 섞지 않고 트리 아래에서 별도로 설명한다.

표현 예시이며 실제 프로젝트 구조가 아니다.

```text
Player [Transform, PlayerActor]
├─ Visual [Transform, Animator]
│  └─ Body [Transform, SkinnedMeshRenderer]
└─ CameraTarget [Transform]
```

## 폴더와 파일
- 디렉터리는 끝에 `/`를 붙이고 파일은 확장자를 포함한 원래 이름으로 표시한다.
- 요청한 루트를 기준으로 나타낸다. 링크·외부 경로를 실제 하위 폴더로 잘못 표현하지 않으며 링크 순환은 펼치지 않는다.
- 생성물·캐시 등 제외한 범위가 있으면 밝힌다. 구조 확인을 위해 파일의 비밀값이나 본문을 불필요하게 출력하지 않는다.

```text
Project/
├─ Runtime/
│  ├─ PlayerActor.cs
│  └─ PlayerMovement.cs
└─ Editor/
   └─ PlayerActorEditor.cs
```

## 다른 구조도와의 경계
- 텍스트 트리를 명시적으로 요청하면 이 스킬을 적용한다. 클래스의 상속 트리 등은 어떤 관계를 가지선으로 나타내는지 밝히고, 상속·참조를 섞어 임의 계층으로 만들지 않는다.
- 표현 방식 지정이 없는 클래스 관계 설명은 class-diagram, 실행 순서·분기·반복의 순서도는 algorithm-flowchart가 담당한다.
- 트리로 온전히 표현하기 어려운 그래프는 참조 표시와 짧은 보충 설명을 사용한다. 사용자가 요청한 형식을 임의로 다른 형식으로 바꾸지 않는다.
