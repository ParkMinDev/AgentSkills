# Class Diagram

## 근거와 범위
- 실제 구조를 설명할 때 관련 선언·필드·생성자·호출부와 수명 관리 코드를 읽고 관계를 판단한다. 이름이나 필드 보관만으로 소유 관계를 추정하지 않는다.
- 설계 제안과 현재 구현을 구분한다. 제공된 코드 밖의 관계는 확인되지 않은 것으로 표시한다.
- 다이어그램 요청만으로 코드를 수정하거나 빌드·실행하지 않는다.
- 핵심 영문 용어는 한국어 의미와 함께 설명하고, 약어는 처음 사용할 때 전체 명칭과 문맥상 의미를 밝힌다.

## 표현 규칙
- 클래스 구조는 Mermaid `classDiagram`으로 표현한다. 텍스트 트리는 명시적으로 요청받았을 때만 사용한다.
- 클래스 다이어그램은 반드시 언어 식별자가 `mermaid`인 코드 블록에 작성하고 첫 줄은 `classDiagram`으로 한다.
- 상자 제목은 `클래스명 : 부모클래스<타입 인자>, 구현인터페이스` 형식으로 표시하며 제네릭 인자를 생략하지 않는다. 인터페이스의 상속도 같은 방식으로 표시하고, 부모 타입이 없으면 이름만 표시한다.
- Mermaid 내부 식별자와 표시 이름을 분리하고, 필요하면 `<`, `>`를 `&lt;`, `&gt;`로 표현한다.
- 모든 관계선에 관계에 맞는 모양과 이름을 함께 표시한다. 상속 `<|--`, 구현 `<|..`, 참조 `-->`, 사용 `..>`, 포함·소유 `*--`, 집합 `o--`. 필요하면 `참조 - 요청 전달`처럼 역할을 덧붙인다.
- 관계선 구분자 `:` 뒤의 설명에는 추가 콜론을 사용하지 않는다. 현재 표시 환경에서 렌더링 실패가 확인되었으므로 `A --> B : 참조 - 요청 전달`처럼 하이픈으로 구분한다. 이 제한은 상자 제목의 콜론에는 적용하지 않는다.
- 참조는 보관 관계, 사용은 일시적 의존 관계에 사용한다. 포함·소유는 소유권과 생명주기 관리 책임이 있을 때, 집합은 독립적인 객체의 전체·부분 관계일 때만 사용한다. 단순히 필드·컬렉션에 보관한다고 소유·집합으로 판단하지 않는다.
- 마름모는 전체·소유자 쪽에 두고, 수량이 중요하면 다중성을 표시한다. 관계가 불명확하면 단정하지 않고 가정임을 밝힌다.
- 함께 표시한 타입의 상속·구현은 제목뿐 아니라 관계선으로도 표현한다. 설명에 불필요한 외부 프레임워크 타입의 별도 상자는 생략할 수 있다.
- 멤버는 생성자, 공개 메서드, 프로퍼티, 이벤트, 생명주기·이벤트 핸들러, 내부 멤버 순으로 역할별 정렬하되 Mermaid의 필드·메서드 구분 범위 안에서 적용한다. 빈 구역과 가짜 구역 제목 멤버는 만들지 않는다.
- 메서드는 매개변수 이름·타입과 반환형을, 필드·프로퍼티는 이름·타입과 접근 수준을 표시한다. 렌더링 호환성을 우선하며, `[get]`, `[get; private set]` 같은 임의 접근자 표기는 멤버에 넣지 않는다. 필요한 get/set 접근 범위는 다이어그램 밖에 설명한다.
- 멤버 타입의 제네릭은 Mermaid가 지원하는 `~T~` 표기를 사용한다. 상자 표시 이름의 제네릭은 위 제목 규칙을 따른다.
- 사용자가 코드나 텍스트로 표시된다고 알리면 같은 다이어그램을 그대로 재전송하지 않는다. 최소 문법의 작은 다이어그램으로 렌더링 여부부터 확인한다.
- 최소 문법도 코드로 표시되면 표시 환경의 문제일 수 있음을 설명하고, 이미지 등 다른 형식으로 임의 전환하지 않는다.
- 주요 멤버만 표시하면 생략 사실을 알리고, 전체 멤버를 요청받으면 임의로 생략하지 않는다.
