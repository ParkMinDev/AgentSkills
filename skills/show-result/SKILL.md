# 결과물 표현

결과물은 작업 후 호출하는 쪽·디스크·파일에 보이는 것이다. 내부 코드 흐름은 결과물이 아니다. 결과물마다 아래 표현 스킬을 골라 쓴다. 각 스킬을 이 대화에서 이미 읽었으면 다시 읽지 않는다.

| 결과물 | 표현 스킬 |
| --- | --- |
| 클래스·인터페이스·공개 API가 생기거나 바뀜 | [show-class-shape](../show-class-shape/SKILL.md) |
| 폴더·파일이 생기거나 없어짐 | [show-text-tree](../show-text-tree/SKILL.md) |
| 파일·설정·명세의 내용이 생기거나 바뀜 | [show-diff](../show-diff/SKILL.md) |

## 예시

예시는 구성만 보여 주며 실제 프로젝트가 아니다.

```text
### • 클래스 형태
(show-class-shape: SaveStore 블록 + 동작 표. 기존 클래스가 바뀌므로 diff로 표시)

### • 폴더 구조
(show-text-tree: slot-1/ 아래 backups/ 추가. 현재 구조가 바뀌므로 diff로 표시)

### • 파일 형태
(show-diff: backups.json. 새 파일이라 json 블록 전체)
```

## 규칙
- **순서**: 클래스 형태 → 폴더 구조 → 파일 형태. 결과물이 있는 것만 `### • 이름` 소제목을 달아 보여 주고, 해당이 없는 것은 생략한다.
- **결과물이 없는 작업**(문서 정리, 측정, 내부 리팩터링 등)은 "결과물 변경 없음"과 이유를 한 줄로 쓴다. 내부 리팩터링이라도 공개 API가 그대로라는 사실이 중요하면 그 한 줄로 밝힌다.
- **같은 결과물을 두 번 보여 주지 않는다.** 예를 들어 새 파일은 폴더 구조에 이름만 두고, 내용은 파일 형태에서 보여 준다. Obsidian 문서에서 diff와 함께 두는 완성본 콜아웃은 예외다.
- **근거**: 계획 단계면 제안이라고 밝히고, 작업 후면 실제 파일·코드에서 확인한 결과만 보여 준다.
