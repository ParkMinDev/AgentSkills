# 게임 흐름 기획서

작업 전에 [예시 캔버스](assets/카페%20영업과%20설정.canvas)를 읽고 표기를 따른다. 예시는 카페의 주문·제작·서빙과 독립된 설정 흐름을 담았다. 예시 파일을 직접 볼 때는 assets를 보관소 루트로 열거나, 캔버스와 화면 시안 폴더를 함께 복사하고 대상 보관소 루트에 맞춰 이미지 경로를 갱신한다.

## 모든 캔버스의 상단

새로 만들 때와 기존 캔버스를 수정할 때 모두 **본문 흐름보다 위에 ‘노드·그룹·연결선 정의’ 범례를 둔다.** 범례가 빠진 기존 파일에는 추가한다. 표기를 바꾸면 범례와 본문에 함께 반영한다.

- 노드 정의는 본문과 동일한 도형 안에 이름과 뜻을 넣는다. 시작·종료는 보라색 캡슐, 장면·행동·상태는 직사각형, 조건 판단은 중앙에 짧은 질문을 넣은 마름모다. 캡슐과 마름모는 Advanced Canvas의 shape와 textAlign 속성을 사용한다.
- 색의 뜻을 따로 정의한다. 초록은 정상 진행과 플레이어의 선택, 주황은 실패나 예외 대응이다. 설정에서 플레이어가 선택한 앱 종료도 정상 진행이다.
- 라벤더색(#B3A1C9) 흐름 그룹은 시작점부터 이어지는 하나의 흐름을 감싼다. 연청회색(#9DBBCB) 기능 그룹은 관련 장면이나 행동을 그 안에 묶는다.
- 연결선 정의는 짧은 노드 두 개와 **실제 화살표**로 그린다. 초록 단방향은 다음 단계, 초록 양방향은 열기·복귀, 주황 단방향은 예외 대응이다. 조건이나 조작을 선에 적는다. 반복은 원래 노드로 직접 돌아가는 일반 단방향 선으로 표현한다.

## 본문과 시안

메인 흐름은 위에서 아래로 읽게 하고, 독립된 흐름은 옆에 둔다. 각 흐름의 첫 장면에 시작 표기를 적용한다. 도구 열기와 결과 반영처럼 왕복하는 기능은 한편에 모아 확장할 자리를 둔다. 실제 종료와 메인 흐름으로의 복귀를 구별한다.

장면 카드는 제목, 핵심 정보, 짧은 설명 순서로 읽게 한다. 이미지가 있으면 설명 아래에 원본 비율로 크게 배치한다. Obsidian에서는 카드 영역 안에 설명 노드와 이미지 파일 노드를 함께 두고 연결선은 바깥 카드에 연결할 수 있다. 현재 구현을 보여 주는 장면에는 그 사실을 표시한다.

노드 치수는 내용에 맞춘다. 연결선의 문구가 카드에 가려지지 않을 만큼 여백을 두고, 같은 기능의 카드 간격을 맞춘다. 기존 노드를 옮길 때는 소속 이미지와 설명도 함께 옮기고 기존 연결을 유지한다.

캔버스는 사용자가 지정한 곳을 우선하고, 기본은 `<프로젝트명>.DevDocs/game-flowchart/`에 둔다. 화면 시안과 현재 구현 이미지는 보관소 루트 기준 경로로 참조한다.
