# Algorithm Flowchart

## 근거와 범위
- 실제 구현 설명이면 관련 함수와 주요 호출부를 읽고 실행 순서·분기·반복·자원 수명을 반영한다. 코드가 없으면 제공된 알고리즘을 근거로 삼고 현재 구현이라고 단정하지 않는다.
- 계획과 구현을 구분한다. 변경 후 순서도는 실제 적용된 코드 기준으로 작성한다.
- 일반 순서도 요청만으로 코드 수정·빌드·벤치마크를 실행하지 않는다. 아래 모드에 따라 실행 범위를 정한다.
- 사용자 언어로 짧고 구체적인 단계명을 쓴다. 핵심 영문 용어는 한국어 의미를 함께 설명하고 약어는 처음 사용할 때 풀어 쓴다.

## 모드 선택
- “순서도 보여줘”: 대상 함수 중심의 단일 순서도를 표시한다. 분리할 가치가 있는 내부 호출은 양옆 이중선 노드로 강조한다. 실행하지 않는다.
- “다중 순서도”, “멀티 순서도”, “함수별로 나눠서”, “순서도 여러 개”, “내부 함수도 별도로” 등 여러 그림으로 펼치려는 의도이면 아래 분리 기준을 적용한다. 특정 문구의 정확한 일치를 요구하지 않는다.
- “② 내부만 펼쳐줘”처럼 범위를 지정하면 해당 부분만 추가한다. 다중 표현과 측정 모드는 조합할 수 있지만, 다중 요청 자체로 실행·측정하지 않는다.
- “측정 포함 순서도 보여줘”, “실행시간도 측정해서 표시해줘”: [references/measurement.md](references/measurement.md)를 읽고 필요한 측정용 빌드·실행과 시간 수집을 수행한다. 이 요청은 대상 알고리즘 측정 범위의 실행을 허용하며, 제품 최적화나 배포를 요청한 것으로 확대하지 않는다.
- “이전 측정 결과로 순서도 보여줘”: 같은 참고 문서에 따라 기존 기록의 코드·입력·환경·시점을 확인해 사용한다. 다시 실행하지 않으며 현재 코드와 다르면 차이를 명시한다.
- 측정 계획만 요청하거나 실행하지 말라고 한 경우에는 실행하지 않는다. 적용되는 사용자·프로젝트 실행 제한을 지킨다.

## 표현 규칙
- 언어 식별자가 mermaid인 코드 블록에 flowchart TD를 기본으로 사용한다. 짧은 흐름은 LR도 가능하다.
- 각 순서도는 맨 위(LR이면 맨 왼쪽)에 캡슐 모양의 시작 노드 하나를 두고 `시작`이라고 명시한다. Mermaid 문법은 `START(["시작<br/>저"])`를 사용한다. 여러 호출 경로는 시작 아래에서 분기하되 실제 실행 관계를 바꾸지 않는다.
- 종료 노드도 캡슐 모양으로 표시하고 `종료` 또는 `반환`을 명시한다. 단계는 사각형, 조건 판단만 마름모로 표시해 시작점과 구분한다. 측정 모드에서 별도 계측하지 않은 시작·종료 표시는 `별도 계측 없음`으로 적고 시간을 만들어 넣지 않는다.
- 각 노드에 <br/> 줄바꿈과 저·중·고를 표기한다. 색상만으로 비용을 전달하지 않는다.
- 단계는 사각형, 판단은 마름모로 표현한다. 분기에는 의미 있는 레이블을 붙인다.
- 반복은 다음 항목으로 진행하는 흐름과 종료 조건이 드러나게 한다. 완료 항목을 무한 반복하는 모양을 피한다.
- 정상 흐름을 중심으로 작성한다. 실패·취소·복구가 핵심이면 분기로 포함하고 아니면 그림 아래 짧게 설명한다. 게시 확정 전후의 실패 처리 차이를 유지한다.
- 실행 순서와 분기 의미를 바꾸지 않는다. 임의의 구현 단계를 추가하지 않는다.
- 출력 순서는 짧은 설명·색상 범례, 순서도, 필요한 조건·실패 설명이다. 코드도 변경했다면 변경 파일과 검증 여부를 별도로 보고한다.
- 렌더링 실패 피드백에는 최소 문법의 작은 그림부터 확인하고 같은 전체 그림을 그대로 재전송하지 않는다.

## 함수별 분리와 호출 표현
- 프로젝트 내부 함수 중 호출자와 구분되는 책임이 있고 분기·반복·병렬 처리·복구·자원 정리 등 의미 있는 흐름을 가진 함수를 분리 후보로 삼는다. 내부를 펼쳤을 때 상위 흐름 이해에 도움이 되는지 판단한다.
- 단순 프로퍼티·값 반환·경로 조합·전달 함수·짧은 입력 검사는 기본적으로 분리하지 않는다. 외부 라이브러리 함수는 역할만 표시한다. 줄 수·노드 수를 절대 기준으로 삼거나 그림 개수를 맞추려고 분리하지 않는다.
- 상위 함수부터 호출 순서에 따라 ①·②·③을 부여하고 실제 파일·함수명을 제목에 연결한다. 부모에는 호출 노드만, 자식에는 해당 함수 내부만 표현한다. 공통 함수는 한 번만 그리고 같은 번호를 참조한다.
- 각 자식 그림의 호출 전제를 명시하고 정상 반환·오류·취소가 부모의 대응 경로로 이어지게 한다. 부모의 잠금 획득 등을 자식 내부 동작처럼 반복하지 않는다. 재귀 호출은 같은 그림 참조로 표시하고 무한히 펼치지 않는다.
- 분리 후보 호출은 Subroutine(하위 처리 절차) 모양인 `CALL[["함수명<br/>고"]]`로 표시한다. 단일 그림에서는 “내부 펼치기 가능”, 다중에서는 “② 참고”처럼 적는다. 시작·종료 캡슐 및 조건 마름모와 구분한다.
- 의미 있는 내부 함수가 없다면 다중 요청이어도 한 그림이면 충분하다고 설명한다. 후보가 너무 많으면 요청 범위의 주요 경로부터 보여주고 생략한 범위를 밝힌다.

## 선 색상
- 노드 색은 처리 비용, 선 색은 실행 결과다. 두 범례를 구분해서 안내한다.
- 정상: `#16A34A`, 오류: `#DC2626`, 사용자 취소: `#EAB308`. 선 두께는 기본 2px, 취소는 가독성을 위해 3px로 표시한다. 모든 의미 있는 분기에 라벨도 붙인다.
- 허용된 파일 누락·변경 없음은 정상 경로다. 오류로 인해 다른 병렬 작업을 내부 취소한 경로는 오류 원인에 따라 빨강으로 표시하며 사용자 취소로 표현하지 않는다.
- 정상·오류·취소가 하나의 정리 노드에 합류하면 들어오는 선은 각 원인 색을 유지한다. 합류 이후 공통 경로는 중립 회색 `#64748B`와 “공통 정리” 라벨을 사용한다. 이후 결과 분기에서 다시 원래 색으로 나눈다. 실제 공통 처리를 색 때문에 서로 다른 알고리즘처럼 복제하지 않는다.
- Mermaid의 `linkStyle default stroke:#16A34A,stroke-width:2px`로 정상 색을 지정하고 오류·취소·공통 경로는 개별 `linkStyle`로 덮어쓴다. 개별 선 번호는 선언 순서의 0부터 시작한다. 화살표를 수정하면 해당 번호도 다시 맞춘다.

## 상대 처리시간
저·중·고는 해당 흐름 안의 상대 비용 표시이며 측정값과 구분한다. 일반 모드에서는 추정이고 측정 모드에서는 실측을 참고하되, 절대 시간과 비율은 실제 기록이 있는 경우에만 표시한다.

- 저: 작은 메타데이터 읽기·저장, 메모리 비교, 조건 판단, 같은 볼륨 내 폴더 이동.
- 중: 경로 목록 순회, 많은 항목 삭제, 내용 전체를 읽지 않는 파일 검사.
- 고: 대용량 전체 파일 읽기·복사·해시, 압축, 델타 생성·시험 적용, 큰 다운로드.
- 위 분류는 기본 판단 기준이다. 데이터량·파일 수·저장 장치·압축 방식·네트워크 조건에 맞게 조정한다.
- 압축하며 해시를 계산한다면 같은 읽기 데이터를 재사용한다는 점을 반영한다. 별도 전체 읽기처럼 중복 비용을 세지 않는다.
- 해시 알고리즘 변경처럼 특정 조건에서 비용이 커지면 단계나 그림 아래에 설명한다.
- 단계 묶음은 지배적인 비용으로 표시하되 비용 원인이 가려지면 분리한다.
- 폴더 이동이 같은 볼륨 내 이동인지, 복사 후 삭제 방식인지 확인한다. 이동을 항상 저비용으로 단정하지 않는다.

모든 노드에 다음 중 하나의 클래스를 지정한다.
```text
classDef low fill:#dcfce7,stroke:#16a34a,color:#14532d
classDef medium fill:#fef9c3,stroke:#ca8a04,color:#713f12
classDef high fill:#fee2e2,stroke:#dc2626,color:#7f1d1d
```
