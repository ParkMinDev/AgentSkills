# Algorithm Flowchart

## 근거와 범위
- 실제 구현 설명이면 관련 함수와 주요 호출부를 읽고 실행 순서·분기·반복·자원 수명을 반영한다. 코드가 없으면 제공된 알고리즘을 근거로 삼고 현재 구현이라고 단정하지 않는다.
- 계획과 구현을 구분한다. 변경 후 순서도는 실제 적용된 코드 기준으로 작성한다.
- 순서도 요청만으로 코드 수정·빌드·벤치마크를 실행하지 않는다.
- 사용자 언어로 짧고 구체적인 단계명을 쓴다. 핵심 영문 용어는 한국어 의미를 함께 설명하고 약어는 처음 사용할 때 풀어 쓴다.

## 표현 규칙
- 언어 식별자가 mermaid인 코드 블록에 flowchart TD를 기본으로 사용한다. 짧은 흐름은 LR도 가능하다.
- 각 노드에 <br/> 줄바꿈과 저·중·고를 표기한다. 색상만으로 비용을 전달하지 않는다.
- 단계는 사각형, 판단은 마름모로 표현한다. 분기에는 의미 있는 레이블을 붙인다.
- 반복은 다음 항목으로 진행하는 흐름과 종료 조건이 드러나게 한다. 완료 항목을 무한 반복하는 모양을 피한다.
- 정상 흐름을 중심으로 작성한다. 실패·취소·복구가 핵심이면 분기로 포함하고 아니면 그림 아래 짧게 설명한다. 게시 확정 전후의 실패 처리 차이를 유지한다.
- 실행 순서와 분기 의미를 바꾸지 않는다. 임의의 구현 단계를 추가하지 않는다.
- 출력 순서는 짧은 설명·색상 범례, 순서도, 필요한 조건·실패 설명이다. 코드도 변경했다면 변경 파일과 검증 여부를 별도로 보고한다.
- 렌더링 실패 피드백에는 최소 문법의 작은 그림부터 확인하고 같은 전체 그림을 그대로 재전송하지 않는다.

## 상대 처리시간
저·중·고는 해당 흐름 안의 상대적인 추정이며 측정 시간이 아니다. 절대 시간이나 성능 향상 수치를 만들어내지 않는다.

- 저: 작은 메타데이터 읽기·저장, 메모리 비교, 조건 판단, 같은 볼륨 내 폴더 이동.
- 중: 경로 목록 순회, 많은 항목 삭제, 내용 전체를 읽지 않는 파일 검사.
- 고: 대용량 전체 파일 읽기·복사·해시, 압축, 델타 생성·시험 적용, 큰 다운로드.
- 위 분류는 기본 판단 기준이다. 데이터량·파일 수·저장 장치·압축 방식·네트워크 조건에 맞게 조정한다.
- 압축하며 해시를 계산한다면 같은 읽기 데이터를 재사용한다는 점을 반영한다. 별도 전체 읽기처럼 중복 비용을 세지 않는다.
- 해시 알고리즘 변경처럼 특정 조건에서 비용이 커지면 단계나 그림 아래에 설명한다.
- 단계 묶음은 지배적인 비용으로 표시하되 비용 원인이 가려지면 분리한다.
- 폴더 이동이 같은 볼륨 내 이동인지, 복사 후 삭제 방식인지 확인한다. 이동을 항상 저비용으로 단정하지 않는다.

모든 노드에 다음 중 하나의 클래스를 지정한다.
```text
classDef low fill:#dcfce7,stroke:#16a34a,color:#14532d
classDef medium fill:#fef9c3,stroke:#ca8a04,color:#713f12
classDef high fill:#fee2e2,stroke:#dc2626,color:#7f1d1d
```
