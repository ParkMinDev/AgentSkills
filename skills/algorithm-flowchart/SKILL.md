# Algorithm Flowchart

## 근거와 범위
- 실제 구현 설명이면 관련 함수와 주요 호출부를 읽고 실행 순서·분기·반복·자원 수명을 반영한다. 코드가 없으면 제공된 알고리즘을 근거로 삼고 현재 구현이라고 단정하지 않는다.
- 계획과 구현을 구분한다. 변경 후 순서도는 실제 적용된 코드 기준으로 작성한다.
- 일반 순서도 요청만으로 코드 수정·빌드·벤치마크를 실행하지 않는다. 아래 모드에 따라 실행 범위를 정한다.
- 사용자 언어로 짧고 구체적인 단계명을 쓴다. 핵심 영문 용어는 한국어 의미를 함께 설명하고 약어는 처음 사용할 때 풀어 쓴다.

## 모드 선택
- “순서도 보여줘”: 대상 함수 중심의 단일 순서도를 표시한다. 분리할 가치가 있는 내부 호출은 양옆 이중선 노드로 강조한다. 실행하지 않는다.
- “큰 덩어리로”: 주요 함수 호출만 표시한다. “큰 영역 안에 세부 노드”, “큰 노드 안에 작은 노드”, “함수별로 묶어서 한 그림에”처럼 한 그림 안의 계층 표현을 요청하면 아래 함수 영역 규칙을 적용한다. 여러 별도 그림 요청과 구분한다.
- “다중 순서도”, “멀티 순서도”, “함수별로 나눠서”, “순서도 여러 개”, “내부 함수도 별도로” 등 여러 그림으로 펼치려는 의도이면 아래 분리 기준을 적용한다. 특정 문구의 정확한 일치를 요구하지 않는다.
- “② 내부만 펼쳐줘”처럼 범위를 지정하면 해당 부분만 추가한다. 다중 표현과 측정 모드는 조합할 수 있지만, 다중 요청 자체로 실행·측정하지 않는다.
- “측정 포함 순서도 보여줘”, “실행시간도 측정해서 표시해줘”: [references/measurement.md](references/measurement.md)를 읽고 필요한 측정용 빌드·실행과 시간 수집을 수행한다. 이 요청은 대상 알고리즘 측정 범위의 실행을 허용하며, 제품 최적화나 배포를 요청한 것으로 확대하지 않는다.
- “이전 측정 결과로 순서도 보여줘”: 같은 참고 문서에 따라 기존 기록의 코드·입력·환경·시점을 확인해 사용한다. 다시 실행하지 않으며 현재 코드와 다르면 차이를 명시한다.
- 측정 계획만 요청하거나 실행하지 말라고 한 경우에는 실행하지 않는다. 적용되는 사용자·프로젝트 실행 제한을 지킨다.

## 표현 규칙
- 언어 식별자가 mermaid인 코드 블록에 flowchart TD를 기본으로 사용한다. 짧은 흐름은 LR도 가능하다.
- 각 Mermaid 코드 블록 맨 앞에 아래 설정을 기본으로 넣는다. 현재 채팅에서 사용자가 선언부 개행과 모양을 확인한 조합이다. `htmlLabels`는 `flowchart` 내부가 아니라 최상위 `config` 바로 아래에 둔다. 자동 줄바꿈을 끄고 `<br/>`로 지정한 위치에서만 줄을 나눈다. 다른 렌더러에서 설정 지원 여부는 별도로 확인하며 모든 환경에서 동일하다고 보장하지 않는다.

```yaml
---
config:
  htmlLabels: false
  markdownAutoWrap: false
  flowchart:
    wrappingWidth: 900
---
```

- 전체 대상 함수를 가장 바깥쪽 `subgraph MAIN` 영역으로 감싼다. 영역 제목은 `클래스명.함수명`처럼 짧게 쓰고, 전체 선언부는 영역 안의 캡슐 모양 시작 노드에 넣는다. 긴 선언부를 영역 제목이나 Mermaid frontmatter의 `title`에 넣지 않는다. 다중 순서도와 내부 보조 함수 영역에도 같은 규칙을 적용한다. 함수가 없는 개념 영역은 역할명만 쓰고 선언부를 만들지 않는다.
- 각 그림과 펼친 함수 영역의 맨 위(LR이면 맨 왼쪽)에 시작 노드를 두고 `시작` 다음 줄에 클래스명·함수 선언부를 표시한다. 예: `START(["시작<br/>Patcher<br/>internal Task RunAsync(<br/>　CancellationToken cancellationToken<br/>)"])`. 호출 흐름은 해당 시작 노드로 진입하게 한다. 별도 선언부 전용 실행 노드는 추가하지 않는다. 개념 순서도의 시작은 `START(["시작"])`로 충분하다.
- 종료 노드도 캡슐 모양으로 표시하고 `종료` 또는 `반환`을 명시한다. 단계는 사각형, 조건 판단만 마름모로 표시해 시작점과 구분한다. 측정 모드에서 별도 계측하지 않은 시작·종료 표시는 `별도 계측 없음`으로 적고 시간을 만들어 넣지 않는다.
- 노드 안에는 저·중·고 글자를 넣지 않는다. 상대 비용은 기존 초록·노랑·빨강 색으로 유지하고 그림 앞에 범례를 짧게 안내한다. 실제 측정시간·미측정·상위 단계에 포함 표시는 유지한다.
- 함수 표시는 클래스명 다음 줄에 접근 제한자·static/async 등 선언된 한정자·반환형·함수명·파라미터를 포함한 선언부로 적는다. 긴 선언은 여는 괄호 다음부터 파라미터를 한 줄에 하나씩 들여쓰고 닫는 괄호를 별도 줄에 둔다. 짧은 선언은 한 줄로 유지할 수 있다. 시작 노드와 펼치지 않은 호출 노드에서 `<br/>`로 개행하고 제네릭의 꺾쇠는 `&lt;`·`&gt;`로 표기한다. 호출 노드는 선언부 아래에 처리 내용을 적는다.
- 파라미터는 `타입 이름 = 기본값` 전체를 한 줄로 유지한다. 타입과 이름 사이, 제네릭 타입 내부, 기본값 앞뒤에는 줄바꿈하지 않는다. 파라미터 사이에만 `<br/>`를 넣고 내부에는 일반 공백을 사용한다. 위 렌더링 설정으로 줄바꿈을 제어하며 `&nbsp;`·특수 공백·노드 CSS 너비 지정으로 우회하지 않는다. 파라미터를 쪼개거나 이름을 생략해 폭을 줄이지 않는다. 시작 노드·호출 노드 모두 같은 규칙을 적용한다.
- 접근 범위는 `public`(공개), `private`(해당 형식 내부), `internal`(같은 어셈블리 내부), `protected`(해당 형식·파생 형식) 등 실제 선언 그대로 표시한다. 선언부에는 `+`·`-`·`~`·`#` 기호를 중복해서 붙이지 않는다. 계획은 `[예정]`을 붙이며 확정되지 않은 선언은 미확정임을 밝힌다. 표현용 제안은 제안이라고 명시하고 실제 구현처럼 단정하지 않는다. 표시를 위해 함수나 타입을 임의로 추가하지 않는다.
- 같은 함수 내부의 조건·반복·단순 처리 노드에 선언부를 반복하지 않는다. 펼친 함수의 선언부는 각 영역의 시작 노드에 한 번만 표시한다. 펼치지 않은 다른 함수 호출 노드는 그 함수의 선언부를 표시하며 파일 링크는 그림 밖에 둔다.
- 단계는 사각형, 판단은 마름모로 표현한다. 분기에는 의미 있는 레이블을 붙인다.
- 반복은 다음 항목으로 진행하는 흐름과 종료 조건이 드러나게 한다. 완료 항목을 무한 반복하는 모양을 피한다.
- 정상 흐름을 중심으로 작성한다. 실패·취소·복구가 핵심이면 분기로 포함하고 아니면 그림 아래 짧게 설명한다. 게시 확정 전후의 실패 처리 차이를 유지한다.
- 실행 순서와 분기 의미를 바꾸지 않는다. 임의의 구현 단계를 추가하지 않는다.
- 출력 순서는 짧은 설명·색상 범례, 순서도, 필요한 조건·실패 설명이다. 코드도 변경했다면 변경 파일과 검증 여부를 별도로 보고한다.
- 렌더링 실패 피드백에는 최소 문법의 작은 그림부터 확인하고 같은 전체 그림을 그대로 재전송하지 않는다.

## 함수별 분리와 호출 표현
- 프로젝트 내부 함수 중 호출자와 구분되는 책임이 있고 분기·반복·병렬 처리·복구·자원 정리 등 의미 있는 흐름을 가진 함수를 분리 후보로 삼는다. 내부를 펼쳤을 때 상위 흐름 이해에 도움이 되는지 판단한다.
- 단순 프로퍼티·값 반환·경로 조합·전달 함수·짧은 입력 검사는 기본적으로 분리하지 않는다. 외부 라이브러리 함수는 역할만 표시한다. 줄 수·노드 수를 절대 기준으로 삼거나 그림 개수를 맞추려고 분리하지 않는다.
- 상위 함수부터 호출 순서에 따라 ①·②·③을 부여하고 실제 파일·함수명을 제목에 연결한다. 부모에는 호출 노드만, 자식에는 해당 함수 내부만 표현한다. 공통 함수는 한 번만 그리고 같은 번호를 참조한다.
- 각 자식 그림의 호출 전제를 명시하고 정상 반환·오류·취소가 부모의 대응 경로로 이어지게 한다. 부모의 잠금 획득 등을 자식 내부 동작처럼 반복하지 않는다. 재귀 호출은 같은 그림 참조로 표시하고 무한히 펼치지 않는다.
- 분리 후보 호출은 Subroutine(하위 처리 절차) 모양인 `CALL[["클래스명<br/>함수 선언부<br/>처리 내용 · 내부 펼치기 가능"]]`로 표시한다. 다중 그림에서는 “② 참고”처럼 적는다. 시작·종료 캡슐 및 조건 마름모와 구분한다.
- 의미 있는 내부 함수가 없다면 다중 요청이어도 한 그림이면 충분하다고 설명한다. 후보가 너무 많으면 요청 범위의 주요 경로부터 보여주고 생략한 범위를 밝힌다.

## 한 그림 안의 함수 영역
- Mermaid `subgraph`(하위 그래프)로 함수 영역을 만들고 짧은 함수명을 제목에 표시한다. 그 안의 시작 노드에 개행된 선언부를 넣고 단계·조건·반복 노드를 이어 배치한다. 실제 함수가 없는 개념 묶음은 역할명만 쓰고 함수 선언이나 인위적인 함수 시작 노드를 만들지 않는다.
- 여러 함수 영역을 같은 그림에 배치할 수 있다. 큰 덩어리 그림의 호출 하나를 해당 함수 영역으로 펼치며, 동일 호출을 별도 실행 단계로 중복 표시하지 않는다.
- 영역 간 선은 실제 진입·반환 지점의 세부 노드를 연결한다. 정상 반환·오류·취소 및 자원 소유 관계는 영역을 펼치기 전과 같아야 한다. 전체 처리에 적용되는 오류·취소 선은 영역에 연결하되 적용 범위를 설명한다.
- 시작 노드에 표시한 선언부를 내부 처리 노드마다 반복하지 않는다. 내부에서 다른 함수를 호출할 때만 해당 호출 노드에 선언부를 표시한다.
- 비용 색은 세부 노드에 적용한다. 함수 영역은 중립적인 기본 외곽선으로 두어 내부 비용과 혼동하지 않게 한다. 영역 전체 실측시간이 있으면 제목에 붙이되 내부 시간과 중복 합산하지 않는다.
- 전체 함수를 감싸는 바깥 영역 안에 내부 함수 영역을 한 단계 펼치는 것을 기본으로 한다. 길거나 선이 복잡해지면 주요 영역만 펼치고 나머지는 이중선 호출 노드로 두거나 다중 순서도로 분리한다. 표현 요청만으로 제품 함수를 재구성하지 않는다.

## 병렬 흐름 영역
- “병렬 흐름”, “파이프라인 구조” 요청이나 일반 순서도에서 병렬 구간을 펼칠 때 적용한다. 동시에 실행하는 전체를 외부 subgraph로 묶고 독립적인 각 흐름을 내부 subgraph로 표시한다. 조건에 따라 한쪽만 실행하는 분기는 병렬로 표현하지 않는다. 영역 하나는 스레드 하나가 아니며 여러 작업자를 포함할 수 있다.
- 전체는 flowchart TD, 병렬 외부 영역 내부는 direction LR로 지정한다. '병렬 흐름 함께 시작' 노드의 실선과 종료 합류 실선은 내부 작업 노드가 아니라 외부 영역 식별자에 연결한다. 병렬 개요에서는 이 규칙을 일반 함수 영역의 세부 진입·반환 연결 규칙보다 우선한다. 내부 왕복선도 자동 배치에 영향을 주므로 정확한 좌표나 같은 높이를 보장하지 않는다.
- 외부 영역은 배경 #111827, 테두리 #64748B, 두께 2px, 제목 흰색. 각 내부 영역은 배경 #172554, 테두리 #60A5FA, 두께 3px, 제목 흰색으로 한다. 개별 노드의 비용색은 유지한다. 일반적인 순차 함수 영역까지 이 색을 적용하지 않는다.
- 실선은 실행 순서·병렬 시작·종료 합류, 점선은 대기열 등을 통한 작업·결과 전달이다. 두 선 형태의 뜻을 그림 앞에 안내한다. 선의 정상·오류·사용자 취소 색은 기존 규칙을 유지하며 전달 내용과 실패 원인을 라벨에 쓴다.
- 대기열이 잠시 빈 상태와 전체 완료를 구분한다. 후속 요청을 만드는 작업이 남아 있으면 종료로 표시하지 않는다. 실제 알고리즘의 전체 완료 조건과 작업자 종료 대기를 명시한다. 좌우 배치를 순차 실행으로 설명하지 않는다.
- 큰 덩어리 요청에는 각 내부 영역에 핵심 처리만 넣고, 상세 요청에는 내부 분기·반복을 펼치거나 별도 그림으로 분리한다. 개념 그림에는 함수 선언을 만들어 넣지 않으며, 실제 함수를 펼치면 기존 시작 노드·선언부 규칙을 유지한다.
- [예시 문서](references/examples.md)의 '병렬 시작·합류'와 '병렬 파이프라인의 작업 전달'을 참고한다. 취소·복구 등을 생략했다면 그림 아래에 범위를 밝힌다.

## 선 색상
- 노드 색은 처리 비용, 선 색은 실행 결과다. 두 범례를 구분해서 안내한다.
- 정상: `#16A34A`, 오류: `#DC2626`, 사용자 취소: `#EAB308`. 선 두께는 기본 2px, 취소는 가독성을 위해 3px로 표시한다. 모든 의미 있는 분기에 라벨도 붙인다.
- 허용된 파일 누락·변경 없음은 정상 경로다. 오류로 인해 다른 병렬 작업을 내부 취소한 경로는 오류 원인에 따라 빨강으로 표시하며 사용자 취소로 표현하지 않는다.
- 정상·오류·취소가 하나의 정리 노드에 합류하면 들어오는 선은 각 원인 색을 유지한다. 합류 이후 공통 경로는 중립 회색 `#64748B`와 “공통 정리” 라벨을 사용한다. 이후 결과 분기에서 다시 원래 색으로 나눈다. 실제 공통 처리를 색 때문에 서로 다른 알고리즘처럼 복제하지 않는다.
- Mermaid의 `linkStyle default stroke:#16A34A,stroke-width:2px`로 정상 색을 지정하고 오류·취소·공통 경로는 개별 `linkStyle`로 덮어쓴다. 개별 선 번호는 선언 순서의 0부터 시작한다. 화살표를 수정하면 해당 번호도 다시 맞춘다.

## 상대 처리시간
저·중·고는 해당 흐름 안의 상대 비용 표시이며 측정값과 구분한다. 일반 모드에서는 추정이고 측정 모드에서는 실측을 참고하되, 절대 시간과 비율은 실제 기록이 있는 경우에만 표시한다.

- 저: 작은 메타데이터 읽기·저장, 메모리 비교, 조건 판단, 같은 볼륨 내 폴더 이동.
- 중: 경로 목록 순회, 많은 항목 삭제, 내용 전체를 읽지 않는 파일 검사.
- 고: 대용량 전체 파일 읽기·복사·해시, 압축, 델타 생성·시험 적용, 큰 다운로드.
- 위 분류는 기본 판단 기준이다. 데이터량·파일 수·저장 장치·압축 방식·네트워크 조건에 맞게 조정한다.
- 압축하며 해시를 계산한다면 같은 읽기 데이터를 재사용한다는 점을 반영한다. 별도 전체 읽기처럼 중복 비용을 세지 않는다.
- 해시 알고리즘 변경처럼 특정 조건에서 비용이 커지면 단계나 그림 아래에 설명한다.
- 단계 묶음은 지배적인 비용으로 표시하되 비용 원인이 가려지면 분리한다.
- 폴더 이동이 같은 볼륨 내 이동인지, 복사 후 삭제 방식인지 확인한다. 이동을 항상 저비용으로 단정하지 않는다.

모든 노드에 다음 중 하나의 클래스를 지정한다.
```text
classDef low fill:#dcfce7,stroke:#16a34a,color:#14532d
classDef medium fill:#fef9c3,stroke:#ca8a04,color:#713f12
classDef high fill:#fee2e2,stroke:#dc2626,color:#7f1d1d
```
