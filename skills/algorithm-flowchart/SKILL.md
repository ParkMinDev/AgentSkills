# 알고리즘 순서도 저장

## 적용 조건과 범위
- 사용자 요청에 “저장”이라는 단어가 있고 순서도를 저장하라는 뜻일 때 적용한다. 일반 “순서도 보여줘”, 계획만 요청한 경우, 저장 금지는 발동 조건이 아니다. 스킬을 명시적으로 지정했다면 요청한 범위에 적용한다.
- 기본 저장 형식은 Obsidian의 `.canvas`다. 설명 문서는 `.md`, 반복 갱신할 측정 표는 `.base`로 연결한다. 사용자가 다른 형식이나 기존 파일 수정을 지정하면 그 선택을 따른다.
- 실제 구현은 대상 함수와 호출부를 읽고 실행 순서, 분기, 반복, 자원 수명을 반영한다. 계획, 가상 예시, 현재 구현을 구분하고 표시를 위해 제품 함수를 만들어내지 않는다.
- 저장만 요청받으면 빌드, 실행, 벤치마크를 하지 않는다. 측정을 요청받았을 때만 [측정 규칙](references/measurement.md)을 읽고 필요한 실행을 한다. 제품 최적화나 배포까지 범위를 확대하지 않는다.

## 저장과 갱신
- 기본 위치는 AGENTS.md의 개발 문서 보관소 규칙에 따른 `<프로젝트명>.DevDocs/flowchart/`이며 Unity 프로젝트도 같다. 사용자 지정 위치와 실제 Obsidian 보관소 루트를 먼저 확인한다. 저장 결과는 버전 관리 대상으로 두고 원시 로그는 프로젝트의 테스트 산출물 위치에 둔다.
- 파일명은 `<클래스 경로>.<함수명> 순서도.canvas`다. 실제 중첩 타입 이름과 `_`를 유지한다. 여러 진입점의 전체 흐름이면 `런처 순서도.canvas` 같은 기존 대표 이름을 유지한다.
- 같은 흐름에 시간을 추가한다고 측정용 Canvas나 Mermaid 문서를 기본으로 복제하지 않는다. 기존 Canvas에 측정값과 조건을 붙인다. 별도 비교본이나 과거 스냅샷은 요청받았을 때 만든다.
- 읽는 방법 카드에 현재 구현/계획, 대상 코드, 갱신일, 범위와 생략, 범례를 적는다. 측정 조건과 상세 기록이 길면 `.md`로 분리해 연결한다.
- 기존 Canvas를 먼저 읽고 노드와 선 식별자, 사용자 배치, 색상과 플러그인 속성을 유지하며 필요한 부분만 바꾼다. 전체 재생성이나 매 갱신마다 일괄 확대하지 않는다. 열려 있는 Canvas의 미저장 편집과 외부 덮어쓰기가 충돌하지 않도록 앱 상태를 확인할 수 있으면 먼저 확인한다.
- `.md` 안에 `![[flowchart/런처 순서도.canvas]]`로 포함할 수 있다. 보관소 밖 경로를 내부 링크처럼 쓰지 않는다. 삭제할 이전 문서의 독자적인 설명을 먼저 보존하고 참조 링크를 수정한다. 스킬 갱신만으로 프로젝트 파일을 일괄 삭제하지 않는다.
- 실제 파일 구조와 연결 예시는 [저장 규칙](references/saving.md)을 읽는다.

## 노드와 함수 선언부
- 위에서 아래로 읽도록 배치한다. 각 독립 흐름에 시작과 종료/반환을 둔다. 단계는 사각형, 판단은 마름모, 시작과 종료는 둥근 모양이다. 분기선에 실제 조건을 표시한다.
- 전체 함수는 바깥 영역으로 감싸고 영역 제목은 짧은 `클래스.함수`로 한다. 선언부는 **영역 안 시작 카드**에 넣는다. 긴 선언부를 영역 제목에 넣지 않는다.
- 선언은 클래스명 다음에 실제 접근 제한자, static/async 한정자, 반환형, 함수명과 인자를 표시한다. 긴 선언은 코드 블록으로 쓰고 인자 하나를 한 줄에 둔다. `타입 이름 = 기본값`은 쪼개지 말고 카드 너비를 늘린다. 선언에 `+/-` 접근 기호를 중복하지 않는다.
- 시작 카드의 선언을 내부 조건이나 처리마다 반복하지 않는다. 펼치지 않은 다른 함수 호출에는 선언부와 역할을 표시하고, 하위 처리 모양 또는 “내부 펼치기 가능” 라벨로 구분한다.
- 실제 함수가 없는 개념 영역에는 역할명만 쓴다. 제안 선언에는 `[예정]`, 예시에는 `[가상 예시]`를 붙인다. 핵심 영문 용어는 한국어 뜻을 함께 설명하며 약어는 처음 풀어 쓴다.

## 함수별 상세 수준
- 기본은 대상 함수의 주요 흐름 하나다. “큰 덩어리”는 주요 호출 중심으로 줄인다. “내부 함수 포함”은 같은 Canvas의 함수별 그룹으로 펼친다.
- 다중, 멀티, 여러 그림 요청은 책임이 구분되는 함수 단위로 나눈다. 분기, 반복, 병렬, 복구가 있어 내부를 펼칠 가치가 있는 함수가 대상이다. 단순 프로퍼티, 경로 조합, 전달 함수를 그림 개수에 맞춰 분리하지 않는다.
- 상위 호출과 하위 영역에 같은 처리를 중복 실행한 것처럼 넣지 않는다. 공통 함수는 한 번 표현하고 호출 위치를 연결한다. 분리한 Canvas에는 상호 링크와 호출 전제, 정상 반환/오류/취소의 대응 경로를 남긴다.
- 실제 잠금과 정리의 소유자를 유지한다. 부모가 잠금을 얻는다면 자식 내부에서 다시 획득하는 흐름으로 그리지 않는다.

## 병렬 영역과 작업 전달
- 동시에 실행하는 전체를 바깥 그룹 하나로 감싸고 각 독립 흐름을 내부 그룹으로 둔다. 내부 그룹은 가로로 나란히 배치하며 대기열은 위, 처리와 반복은 가운데, 결과 이벤트는 아래에 둔다. 조건에 따라 하나만 실행하는 분기를 병렬로 그리지 않는다.
- 시작 실선은 병렬 바깥 그룹에 연결하고 바깥 그룹에서 전체 합류/작업자 종료 대기로 연결한다. 영역 하나는 스레드 하나를 뜻하지 않는다. 각 영역에 실제 작업자 수와 실행 조건을 적는다.
- 실선은 실행 순서와 시작/합류, 점선은 대기열과 이벤트를 통한 작업/결과 전달이다. 이벤트마다 별도 노드와 전달 내용 라벨을 두고 실제 연결을 표시한다. 요청을 받는 대기열과 내부 반복으로 돌아가는 경로도 표시한다.
- 일시적으로 큐가 빈 상태와 전체 완료를 구분한다. 다른 흐름이 후속 요청을 만들 수 있다면 빈 큐를 종료 조건으로 그리지 않는다. 모든 대상 완료와 작업자 종료 대기를 반영한다.
- 병렬 바깥 영역은 짙은 중립색 `#111827`/테두리 `#64748B`, 내부는 짙은 파랑 `#172554`/테두리 `#60A5FA`를 기준으로 한다. 흰 배경을 강제하지 않으며 기존 테마와 색을 유지한다. 기본 Canvas에서 지원하지 않는 배경/테두리 분리는 플러그인이나 명시적인 스타일 기능이 있을 때만 적용한다.

## 색상과 변경 강조
- 노드 색은 상대 비용이다. 초록은 가벼운 처리, 노랑은 중간, 빨강은 큰 읽기/압축/다운로드 등이다. 노드 안에 저/중/고 글자를 넣지 않는다. 함수 영역은 중립색, 공개 진입/반환은 보라, 이벤트는 하늘색을 쓸 수 있으며 범례에 뜻을 적는다.
- 색은 실제 비용에 맞춰 판단한다. 같은 볼륨 이동과 복사 후 삭제를 구분하고, 같은 읽기 데이터로 해시와 저장을 함께 처리한다면 전체 읽기를 두 번으로 세지 않는다. 입력 크기, 장치, 네트워크에 따른 차이를 명시한다.
- 선은 정상 `#16A34A`, 오류 `#DC2626`, 사용자 취소 `#EAB308`, 공통 정리 `#64748B`다. 이벤트 전달은 파랑 점선으로 구분할 수 있으며 실제 의미를 라벨에 쓴다. 허용된 누락은 정상이고 오류로 인한 내부 취소는 사용자 취소와 다르다.
- 이번 수정 직전과 비교해 추가/변경된 노드만 기존 비용색을 유지한 **10px 테두리**로 강조한다. 다음 갱신에서 내용과 역할이 같으면 원래 굵기로 되돌리고 이전 강조를 누적하지 않는다. 새 Canvas는 기본 테두리를 쓴다. 지원하지 않는 굵기 속성을 임의로 만들지 말고 아래 확장 규칙을 따른다.
- 메모리 피크 강조는 변경 강조와 별개다. 비교 가능한 같은 대표 회차에서 최대 전용 메모리가 실제로 관측된 **개별 노드에만 빨간색 외곽 광택**을 적용한다. 함수/병렬/파이프라인 그룹에는 광택을 적용하지 않고 시간과 최대 메모리 수치만 남긴다. 기존 도형, 배경, 비용색과 연결선은 유지한다. 세부 선정 기준은 [측정 규칙](references/measurement.md)을 따른다.
- 삭제는 Canvas 하단의 “삭제된 노드” 카드에 한 노드당 번호와 `클래스.함수(): 삭제 전 내용`을 적는다. 이번 삭제 목록으로 교체하고 삭제가 없으면 이전 목록을 제거한다. 계획 단계 함수는 예정임을 표시한다.

## Canvas 형식과 확장 기능
- `.canvas`는 노드와 연결선을 담는 JSON이다. 노드 식별자, 좌표/크기와 텍스트, 선의 출발/도착 식별자를 유지한다. 그룹의 포함 관계는 좌표로 표현되므로 부모 그룹 안에 자식을 배치하고 부모를 앞에 저장한다.
- 마름모, 둥근 노드, 점선은 Advanced Canvas 확장을 이용한다. 사용 가능할 때 `styleAttributes.shape`의 `diamond`, `pill`, `predefined-process`와 선의 `styleAttributes.path: dotted`를 사용한다. 지원 여부를 모르는 속성을 추측해 쓰지 않는다.
- 10px 테두리와 외곽 광택은 기본 JSON Canvas나 기본 `borderWidth` 속성으로 보장되지 않는다. Advanced Canvas와 보관소 CSS 조각을 쓸 수 있다면 [강조 스타일](assets/canvas-node-emphasis.css)의 `revisionEmphasis: current`와 `memoryPeak: observed`를 각각 필요한 `styleAttributes`에 추가한다. 두 표시는 독립적이며 피크라는 이유만으로 변경 테두리를 붙이지 않는다. CSS를 실제로 불러오고 활성화해야 한다. 기존 `shape`, 색상과 다른 속성을 보존한다.
- 스타일은 마름모의 도형 전용 테두리 변수와 일반 노드 테두리를 구분하며 원래 색상을 바꾸지 않는다. 광택은 밝은 빨강의 가까운 빛과 넓은 빨강의 바깥 빛을 겹치고 배율 보정으로 줌아웃 시 가독성을 유지한다. 보관소의 줌 설정 자체는 변경하지 않는다. 스타일 속성만 저장하거나 글자만 굵게 써놓고 실제로 적용됐다고 보고하지 않는다.
- 확장이 없으면 “분기”, “시작/반환”, “이벤트 전달” 라벨로 의미를 유지하고 도형과 점선 제한을 밝힌다. 플러그인 설치, 전역 설정 변경, CSS 추가는 해당 작업 범위에서 허용된 경우에만 한다.
- 카드 글자가 잘리면 카드 크기와 간격을 조정한다. 특히 마름모는 중앙 유효 폭이 좁다. 확대/축소 설정은 임의로 바꾸지 않으며 렌더링 실패 피드백을 전체 그림 재전송으로만 처리하지 않는다.
- 형식과 최소 예시는 [예시](references/examples.md)에 있다. Mermaid는 채팅 표시 또는 명시적 요청에만 사용할 수 있으며 Canvas 대신 중복 원본으로 기본 저장하지 않는다.

## 완료 보고
- 생성/수정/삭제 파일과 클릭 가능한 링크를 제공한다. Canvas는 파일 링크로 열게 하고 `.md`에 필요하면 포함한다. 채팅이 Canvas를 직접 렌더링한다고 가정하지 않는다.
- 측정 여부, 미측정 범위와 수행/생략한 검증을 구분한다. 사용자가 각 스킬이나 문서를 읽고 싶어 하면 본문과 예시를 직접 열 수 있는 링크를 준다.
