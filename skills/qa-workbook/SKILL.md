# 엑셀 검증대장

- “검증하고 반영해줘”는 요청한 범위의 테스트를 실행하고 결과를 기록한다. “결과를 반영해줘”는 이미 관찰한 결과를 기록한다. “남은 검증 알려줘”는 대장을 읽어 미완료 조건을 정리한다. 테스트 실행 시 해당 프로젝트의 검증 지침을 따른다.
- 사용자가 지정한 파일을 우선한다. 경로가 없으면 프로젝트의 기존 검증대장을 찾는다. 새 대장과 증거의 저장 위치는 적용되는 `AGENTS.md`를 따른다. 별도 경로 지정이 없으면 Unity는 `Assets/Ignore/<작업명>/`, 일반 프로젝트는 저장소 루트의 `Ignore/<작업명>/`, 저장소가 없으면 프로젝트 루트의 `Ignore/<작업명>/`를 쓴다.
- 기본 열은 번호, 테스트 항목, 판정, 확인한 결과, 남은 검증, 사진 증거다. 테스트 항목에는 시작 조건, 조작, 관찰 대상, 통과 기준을 쓴다. 실제로 사용한 빌드와 환경, 확인한 화면이나 측정값은 결과에 기록한다.
- 서버 검증만 성공했다면 서버 통과로 기록한다. 클라이언트 양쪽 화면이나 배포 빌드 확인이 필요한 항목은 완료될 때까지 남은 검증에 구체적으로 적는다. 재현에 실패하거나 환경 문제로 실행이 막히면 그 이유와 남은 조건을 적는다.
- 사진 증거는 같은 메인 표의 해당 행에 설명이 있는 클릭 가능한 텍스트 링크로 넣는다. 기본 증거는 스크린샷만 남긴다. 사진과 엑셀을 함께 옮길 수 있으면 파일 기준 상대 경로를 쓴다. 이동이나 갱신 후에는 링크 대상이 실제로 존재하는지 확인한다.
- 기존 엑셀은 같은 경로에 갱신하고 항목 번호, 관계없는 행 및 기존 사진 링크를 보존한다. 생성 스크립트나 원본 데이터가 있으면 다음 생성 때 수정 내용이 유실되지 않도록 실제 원본도 갱신한다. 폴라리스 등에서 파일을 잠그고 있으면 변경분을 준비하고 해당 문서 탭이 닫힌 뒤 같은 파일에 반영한다.
- 파일 작업은 사용 가능한 스프레드시트 도구와 지침을 따른다. 최종 보고에는 갱신한 대장 링크, 바뀐 항목, 실제 수행한 검증과 남은 조건을 적는다.

명시적 호출 예시
- `$qa-workbook 새 검증대장 만들어줘.`
- `$qa-workbook 13번 검증하고 스샷을 검증대장에 반영해줘.`
