# Text Tree

표기는 아래 예시를 따른다. 예시는 표현 방식만 보여 주며 실제 프로젝트 구조가 아니다. 예시로 보이지 않는 판단 규칙만 글로 적는다.

## 예시

폴더와 파일:

```text
Project/
├─ Runtime/
│  ├─ PlayerActor.cs           — 입력을 받아 이동·공격을 조율
│  └─ PlayerMovement.cs
├─ Editor/
│  └─ PlayerActorEditor.cs
├─ Shared/ → Packages/Shared/ 참조
└─ … (Tests/, Samples/ 생략)
```

Unity GameObject와 Component (한 줄이 GameObject 하나, 부착 Component는 `[ ]` 안에 나열):

```text
Player [Transform, PlayerActor]
├─ Visual [Transform, Animator]
│  └─ Body [Transform, SkinnedMeshRenderer]
├─ HUD [RectTransform, Canvas, CanvasScaler]
│  └─ HpBar (비활성) [RectTransform, Image, Missing Script]
└─ CameraTarget [Transform]
```

- `PlayerActor.target` → `CameraTarget` (참조 필드는 계층에 넣지 않고 트리 아래에 적는다)

일반 계층 (관계 기준을 트리 앞에 한 줄로 밝힌다):

가지선은 "상위 분류에 속한다"를 뜻한다.

```text
게임 시스템
├─ 전투
│  ├─ 공격 판정
│  └─ 피해 계산 → 경제/보상 참조
└─ 경제
   └─ 보상
```

## 판단 규칙
- **근거**: 실제 구조는 소스·파일 목록·에디터 조회 결과로 확인하고 쓴다. 설계 제안, 사용자 제공 정보, 실제 조회 결과를 구분한다.
- **없는 계층을 만들지 않는다.** 설명을 위해 다시 분류했다면 설명용 분류라고 밝힌다. 관계나 범위가 불명확하면 문맥으로 정하고, 선택에 따라 의미가 크게 바뀌는데 근거가 없을 때만 묻는다.
- **원래 이름과 순서를 지킨다.** 실제 순서에 의미가 있으면 보존하고, 정렬·생략으로 의미를 바꾸지 않는다. 동명이인은 경로나 식별 정보로 구분한다. 확인하지 않은 상태나 관계는 단정하지 않는다.
- **생략**: 주요 항목만 보이면 생략한 범위를 밝힌다. 전체를 요청하면 임의로 생략하지 않고, 크면 루트별로 나눈다. 생성물·캐시를 뺐다면 밝힌다.
- **공유·순환 항목**은 정식 위치 한 곳에만 펼치고 나머지는 `→ 참조`로 둔다. 참조를 실제 소유·하위 관계로 바꾸지 않는다. 링크·외부 경로도 실제 하위 폴더처럼 펼치지 않는다.
- **Unity**: 실제 확인한 컴포넌트만 쓴다. Transform과 RectTransform을 혼동하지 않고, 같은 타입이 여러 개면 중복을 보존하거나 개수를 적는다. 일부 컴포넌트만 보였다면 생략을 밝힌다. 비활성·누락 스크립트는 확인했고 설명에 필요할 때만 표시한다.
- **설명 덧붙이기**: `— 역할 설명`은 필요한 항목에만 붙인다. 핵심 영문 용어는 한국어 의미를, 약어는 처음에 전체 이름을 함께 쓴다. 실제 이름과 코드 식별자는 번역하지 않는다.
- **구조를 바꾸지 않는다**: 표현 요청만으로 파일·씬·프리팹을 고치거나 빌드·재생하지 않는다. 구조 확인을 위해 비밀값이나 파일 본문을 출력하지 않는다.
- **달라지는 모양**: 기존 것과 달라지는 모양을 보여 줄 때는 [show-diff](../show-diff/SKILL.md)를 따른다. 이 대화에서 이미 읽었으면 다시 읽지 않는다.
